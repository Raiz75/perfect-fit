# Admin Dashboard PDF Report — Design Spec

**Date:** 2026-07-29
**Status:** Approved for implementation
**Project:** PERFIT (Laravel 12 migration)

## Overview

Add a "Generate Report" button to the admin dashboard that exports the currently filtered dashboard data (stat cards, charts, data table) as a PDF file using Dompdf — including applied filters, server-side rendered chart images, and styled data tables. The report mirrors the format from the legacy `perfit-old/perfit/` codebase.

## Route & Controller

**Route:** `POST /admin/dashboard/report` → `Admin\ReportController::generate()`
**Name:** `admin.dashboard.report`
**Middleware:** `admin` (authenticated)

The controller:

1. Reads filter params from the request: `search`, `startDate`, `endDate`, `gender`, `marital`, `baptized`, `faith`, `age`, `skills` (comma-separated), `ministries` (comma-separated)
2. Queries `UserReport::where('church_code', $user->church_code)` with the same filter chain as `DashboardController::getData()`
3. Computes aggregated chart data (same bucketing as `admin-dashboard.js`):
   - **Gender** — count by gender
   - **Age** — bucket into Under 18 / 18-25 / 26-35 / 36-50 / 51+
   - **Baptized** — count Yes/No
   - **Faith** — count by 4 time_in_faith buckets
   - **Skills** — count each of 8 boolean skill columns
   - **Ministry** — split `eligible_ministry` CSV, count per ministry
   - **Marital** — count Single/Married
4. Generates chart images via `ChartImageService`
5. Passes everything to the Dompdf view
6. Returns `$pdf->stream()` (download)

## Chart Rendering (Server-Side)

**Library:** `cpchart/cpchart` (pChart 4.0) — pure PHP, renders to PNG/GD

**ChartImageService methods:**

- `renderPie(array $labels, array $data, array $colors, string $title): string` — returns PNG binary
- `renderBar(array $labels, array $data, array $colors, string $title): string`
- `renderDoughnut(array $labels, array $data, array $colors, string $title): string`

**Color palette** — matches frontend `admin-dashboard.js` exactly:
- Gender: `#E6194B`, `#F58231`
- Age: `#9A6324`, `#FFD8B1`, `#808000`, `#AAFFC3`, `#FF7F50`
- Baptized: `#3CB44B`, `#808080`
- Faith: `#FFE119`, `#BFEF45`, `#3CB44B`, `#46F0F0`
- Skills: `#E6194B`, `#F58231`, `#FFE119`, `#BFEF45`, `#3CB44B`, `#46F0F0`, `#4363D8`, `#911EB4`
- Ministry: HSL-distributed (matching JS: `hsl(${(i * 360) / labels.length}, 70%, 60%)`)
- Marital: `#800000`, `#808080`

Each chart is rendered to a temporary PNG in `storage/app/report-charts/`, embedded in the Dompdf view via `<img src="{{ $chartPath }}">`, then cleaned up after PDF generation.

## Frontend Integration

**Button:** A "Generate Report" button added in the dashboard filter bar (`.admin-glass-filters`), next to "Apply Filters" and "Reset" buttons.

**Behavior on click:**
1. JS collects current filter values (same fields as `loadDashboardData()`)
2. Creates a hidden `<form method="POST" action="/admin/dashboard/report">` with CSRF token + filter inputs
3. Submits the form — the server streams back the PDF as a download
4. **File name:** `{ChurchName}_Dashboard_Report.pdf`

**Edge cases handled:**
- **No data matches filters** — Report still generates with a "No records found" message in the summary and empty tables
- **No filters applied** — Report period shows "All Available Data"
- **Missing date range** — Acceptable, just shows "All Available Data"
- **Invalid date range** — Client-side validation prevents start > end (already exists in dashboard.js)

## Error Handling

| Scenario | Behavior |
|----------|----------|
| pChart fails to render | Skip chart image, show data table only |
| Dompdf memory limit | Log warning, return truncated PDF |
| Unauthenticated | Redirect to admin login (middleware handles) |
| No UserReport records | Generate report with "No data" message |
